01 — THE WHOLE RUN

One request, end to end

The path a review actually takes, from the click to the four things it leaves behind. The three compute stages are the spine; everything hanging off it is a guard, a cache, or a store.

02 — THE CENTRAL CLAIM

What each stage is allowed to see

This is the diagram the product's argument rests on. The failure mode being designed out is not bad reasoning — it is a model answering from recall with the same confidence it answers from evidence. The fix is an information boundary, not a better prompt.

03 — RETRIEVAL FAN-OUT

How one domain becomes many Paperclip commands

Each active domain declares its own search steps, and each step names a scope that expands into one or more real commands. This is why a Phase 3 asset costs far more than a preclinical one — and why the expense is itemised in the trace.

04 — PHASE GATING

Nine domains, activated by development phase

A preclinical asset is never asked for postmarketing controls it cannot have. Inactive domains are not silently skipped — they enter the dossier marked not_applicable, so the reader can tell a missing answer from an inapplicable question.

05 — THE RUBRIC

Ten weighted dimensions, checked at module load

The shape is deliberate and it is not the shape you would use for a small molecule: long-term genetic risk and biodistribution carry as much weight as CMC, because for an integrating vector or an in vivo editor those dimensions are the review.

07 — SIDE SYSTEMS

Everything optional, and what happens without it

Four integrations are additive. Each one has a defined behaviour when it is absent, and absent is the default — no surface breaks, and none of them silently substitutes something plausible.

Paperclip · required

Evidence retrieval

Hosted MCP server exposing one tool whose only argument is a CLI command string. Without a key, health reports it and runs refuse before spending anything.

Model · required

Extraction + scoring

Anthropic by default (claude-opus-5), or any OpenAI-compatible endpoint via MODEL_PROVIDER. Structured output with a JSON schema — no parse-and-retry loop.

Benchling · optional

Real construct sequences

Tenant-scoped DNA/AA sequence lookup by therapeutic name. Unconfigured or unmatched → the modality-derived schematic renders, and the panel says it is architecture only.

Modal · optional

Two GPU jobs

Folding a sequence into a structure, and grounding a claim to a passage. Separate endpoints and protocols per task, since a structure predictor and a language model are rarely one deployment.

MongoDB · optional

Durable audit memory

Every run writes an audit record. With MONGODB_URI set they go to a collection; otherwise to disk; and on a read-only filesystem, to a process-lifetime memory cache.

ClinicalTrials.gov · build-time

Registry enrichment

Read-only v2 API, batched 50 ids per request, no key. Registry values beat extracted ones for sponsor, phase and start date; observational studies are dropped.

08 — CATALOG BUILD

The offline pipeline that fills the picker

Run separately with npm run catalog. It is the same philosophy in miniature: where a source cannot supply a field, go to the authoritative source rather than letting a model guess and calling the guess data.

09 — THE BROWSER

One workstation, zero third-party JavaScript

The interface is not a report with a chart on it — it is a single workstation whose centre panel is the run itself, driven by the same SSE events the console prints.
